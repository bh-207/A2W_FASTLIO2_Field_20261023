Outcome
Same-factor batch LM with independently verified small actual-objective gradients
does NOT remove the substantial fixed-correspondence damage seen in v2/v3.
This rules out insufficient iSAM2 iterations as the sole explanation for these
particular heldout seams, not every possible optimizer/backend problem. It is
evidence of mismatch between the frozen measurements/model and heldout geometry,
not absolute ground-truth proof of any individual false loop. Quality remains
NOT_ACCEPTED; no Bundle/map is produced or published.

Numerical audit: residuals, noise, weights and costs
Each *_factors.csv records explicit SE3 Log AND factor.unwhitenedError() six
vectors. Order is rotation xyz in radians, then translation xyz in metres. It
also records factor.unweightedWhitenedError() (underlying Gaussian whitening),
factor.whitenedError() (noise whitening including robust IRLS reweight), their
norm-ratio actual IRLS block weight, factor.weight(values), factor.error(values),
canonical rho(Gaussian-whitened norm), Gaussian reference cost and IRLS quadratic
surrogate. Factor cost sums are checked against graph.error(values).
The actual native residual and explicit SE3 Log agree to floating precision
(installed GTSAM_POSE3_EXPMAP is enabled). This convention is never radians/degrees
or rotational/translational sigma mixed into a single unwhitened threshold.

Original unchanged sigmas:
  prior rotation 0.001 rad; prior translation 0.001 m
  odom rotation 0.05 rad; odom translation 0.1 m
  loop rotation 0.05 rad; loop translation 0.1 m
  original robust kernel Huber, block norm, k=1 whitened units
These are configured model sigmas, not empirically calibrated covariance truth.
Each loop has the same diagonal sigmas as one odometry factor; this says nothing
by itself about independence or whether the sigma is well calibrated.

Important installed GTSAM 4.1.1 API characterization (production library unchanged):
  Fixture native Log = [0.1,0,0,0,0.4,0], Gaussian whitening = [2,0,0,0,4,0].
  Huber actual WhitenSystem IRLS weight = 1/sqrt(20) = 0.22360679775.
  factor.weight(values) instead returns 1 because its robust.weight sees the
  native residual norm, not the underlying Gaussian-whitened norm.
  factor.error = sqrt(sqrt(20))-0.5 = 1.6147425268811286;
  canonical Huber rho(sqrt(20)) = sqrt(20)-0.5 = 3.97213595499958.
  Separate Cauchy fixture native translation .2m (Gaussian norm2) gives actual
  IRLS weight .2; factor.weight = 1/1.04 = .9615384615384615;
  factor.error = .5*ln(1.8) = .29389333245105947;
  canonical Cauchy rho(2) = .5*ln(5) = .8047189562170501.
  The installed Robust inherits Base::squaredMahalanobisDistance, which calls
  robust whiten(v) (already IRLS weighted); Robust::loss then applies rho to that
  norm. Thus graph.error and the canonical IRLS objective are not generally the
  same nonlinear function outside the quadratic regime. The tool does NOT replace
  this cost or modify GTSAM. It reports both, and checks actual cost derivatives.
  This is why factor.weight API is NOT labelled the actual linearization weight.
  The installed header and shared-library hashes are preserved in graph/.
  Primary reference supporting this code path:
  https://raw.githubusercontent.com/borglab/gtsam/4.1.1/gtsam/linear/NoiseModel.cpp
  (Base::squaredMahalanobisDistance and Robust::WhitenSystem), plus local
  /usr/include/gtsam/linear/NoiseModel.h Robust::loss/weight and tested library APIs.

Crucially: EVERY final loop in clean/v2/v3 iSAM AND final batch has actual Huber

Why exact batch Jacobians are used
The installed BetweenFactor default fast path returns Between Jacobians without
multiplying by the Local-chart derivative. Its own header has the alternative
GTSAM_SLOW_BUT_CORRECT_BETWEENFACTOR path. The first standard-Jacobian runs stopped
with IRLS linearization gradient <1e-6, but numerical actual-cost gradient was
0.00683 (v2) / 0.00770 (v3). Those are explicitly NOT_CONVERGED artifacts.
The standalone ExactBetweenFactor subclasses the SAME GTSAM BetweenFactor and
restores only that Local-chain derivative. Measurements, residual, noise, robust
cost and factor directions remain identical. No global compile macro or library
ABI is changed, and original production iSAM still uses its unchanged code.
A dedicated RED->GREEN test verifies the same residual and all six Jacobian
columns against central differences at a nonzero SE3 error. Frozen iSAM replay
with the original backend matches every supplied original pose exactly (max
translation0, rotation about4e-18rad); this verifies the original factor/noise setup.

endpoint, raw source translation/rotation and source timestamp gap. Support uses

the data do not establish that this independence/noise model is calibrated.

Interpretation and next evidence, not a policy change
The batch result supports investigating measurement observability/multi-surface
consistency and correlation-aware information modelling; it does NOT justify
blanket sigma increases, uniform loop downweighting, post-hoc ID deletions or
threshold relaxation. Low actual graph residual and Huber weight1 can coexist
with worse heldout seam correspondence. Odom residual growth alone is expected
when a graph redistributes inconsistency and is not a sufficient map-bad test.
No gravity/roof causality, absolute localization accuracy, physical horizon or
zero false-loop rate is established. Original factory map tilt/slope is preserved
as input evidence, not converted to a target to force horizontal.
