坐标核对
归档驱动 frame_normalization 对点云/角速度/加速度各旋转一次，只有旋转，无平移；SDK transform_flag=false，x/y/z=0。
aligned表示轴向归一化，不能据此认为LiDAR与IMU原点重合。
FAST-LIO：p_camera_init = R_camera_init_I*(R_I_L*p_L+T_I_L)+p_camera_init_I。
本次T按照用户指定值解释为aligned IMU坐标中的LiDAR原点；不反号、不额外旋转，不复制驱动归一化矩阵。
没有发现归档中已经应用这组非零平移的证据。该数值原始测量坐标/精度及当前远端是否仍与归档完全一致待现场核实。
body→base_link安装变换是另一条关系，本次不拿它替代LiDAR—IMU外参。

终端一：环境、会话绑定和最小录包
接好机器人有线网络后执行（&&保证上一步失败就不会继续）：

cd /home/bh/A2W_FastLio2_controlled
export SESSION=/home/bh/A2W_FastLio2_controlled/captures/field_fixed_sessions/fixed_short_20261023_001
source experiments/field_fixed_20261023/env.sh && \
./experiments/field_fixed_20261023/capture.sh bind-network "$SESSION" && \
source "$SESSION/session.env" && \
./experiments/field_fixed_20261023/capture.sh check "$SESSION" && \
./experiments/field_fixed_20261023/capture.sh record "$SESSION"

record是前台长任务，保持终端开启。必须看到RAW_RECORDING_OBSERVED；它表示独占录包器端点和两个原始话题已观察到，不等于无丢包或INIT通过。
固定实际参数：128MiB=134217728 bytes、无压缩、SQLite resilient WAL、512MiB或300秒分段；双缓冲可能使用两倍缓存。
只请求六个话题：/lidar_points /lidar_imu /Odometry /tf /tf_static /mapping/registration_status。
record_settings.json记录实际命令；缓存容量本身不是无丢包证据。
不要在建图未保存时直接关终端一。录包告警Cache buffers lost messages或Total lost>0会标记降级。

终端二：输入核对、固定外参建图、真实ready
保持静止，在新终端执行：

cd /home/bh/A2W_FastLio2_controlled
source captures/field_fixed_sessions/fixed_short_20261023_001/session.env && \
./experiments/field_fixed_20261023/capture.sh inputs "$SESSION" && \
./experiments/field_fixed_20261023/capture.sh start "$SESSION" && \
./experiments/field_fixed_20261023/capture.sh params "$SESSION" && \
./experiments/field_fixed_20261023/capture.sh ready "$SESSION" --timeout 120

inputs必须valid=true，检查真实frame、字段、发布者QoS、持续输入、当前host/sensor差不超过2秒、同会话录包PID与端点及实际128MiB设置。
check只验软件/冻结契约，inputs和start才检查当下真实数据；SSH成功不能代替。
若时钟差超限，停止本会话采图后按已确认流程校时，再新建会话；不能把主机时差填入LiDAR—IMU offset。
start会打印前端二进制、会话配置、完整R/T及false；完整版本和动态库身份另存JSON。
params来自直接参数服务（不使用旧ROS CLI daemon缓存），同时检查实际KEEP_LAST100/BEST_EFFORT。
ready必须ready=true、真实INIT_COMMIT及时间一致性通过、至少一条真实POST、fixed_state.valid=true；backend必须有新鲜state=receiving状态且processed>0，不能仅前端ready而后端未处理关键帧。
C++在初始化完成及每次激光更新后检查实际R/T；发生变化会报错退出，不会把数值强行夹回目标。
ready失败：继续静止，读init_quality.csv、raw_input_report.json、logs/frontend.log；不放宽20ms门，不将Odometry或started当作ready。
只有ready通过后才由用户现场手控小范围短闭环；本入口不发布运动命令。
首次短闭环结束后先保存核查，再为全厂另建新会话；本次准备不认证全厂地图精度。

结束：先停止手控行走，再保存、排空、正常退出
仍用终端二、保持静止：

./experiments/field_fixed_20261023/capture.sh save "$SESSION" --timeout 600

必须成功返回success=true，且drain.received==drain.processed、pending==0、active="none"，Bundle manifest验证通过。
保存服务先冻结后端接收截止，再排空并保存；当前回环随KF同步执行，此时无在途关键帧/回环任务。
若超时，不重复保存，不强杀；后端可能仍在排空，继续检查logs/backend.log。
保存成功后再执行：

./experiments/field_fixed_20261023/capture.sh stop "$SESSION"

终端一应正常返回。终端三按Ctrl+C停止监视，然后终端二执行：

./experiments/field_fixed_20261023/capture.sh verify "$SESSION"

verify必须等录包退出/metadata写入后再执行。检查field_verification.json：
- capture_degraded=false；record_closed.exit_code=0；没有缓存丢失告警；Bag覆盖包含前端启动前原始数据；
- runtime.valid=true且attempted=enqueued=written=CSV行数，closed/flush_ok=true，dropped/write_errors=0；
- fixed_state.valid=true，所有INIT/POST的R/T正确；
- imu_callback_vs_bag.valid=true，在callback覆盖的整数传感器时间区间精确按重复次数核对；
- handoff.valid=true，首POST进入首KF，保存截止范围无静默丢失；截止之后仍在继续的传感器/前端尾部单独列出，不算入已保存地图。
- missing_topics必须逐项看；没有/tf_static发布者时不伪造TF，不得称六话题完整；有发布者却未录到则失败。
任何失败保留Bag/日志/Bundle为降级证据，不把退出0或Bundle存在当作精度/输入连续性通过。
